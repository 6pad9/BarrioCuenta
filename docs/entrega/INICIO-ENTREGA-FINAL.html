1. Recorrido para exponer (8–10 minutos)

  1. Problema y perfiles (1 min). Explicar el crédito de pequeños comercios y la independencia entre tiendas. Mostrar las tiendas con una cuenta del sistema.
  2. Negocio y cliente (2 min). Entrar con el administrador de negocio de Mi Tienda Test. Abrir Clientes y buscar “DEMO Presentación”. Mostrar moneda, límite S/ 3,000, tasa compensatoria 2% mensual y mora 3% mensual.
  3. Cuotas (2 min). Abrir “DEMO Presentación - Tres cuotas”, venta V-2, cronograma. Compra simulada 15/09/2026 por S/ 1,000; gracia 11 días; financiado S/ 1,007.29; cuotas S/ 349.28, 349.28 y 349.29. Primer vencimiento 26/10/2026.
  4. Estado al corte (1 min). Consultar septiembre y octubre. La primera cuota del plan entra en octubre. Explicar que el estado conserva el corte y la cobranza recalcula la mora a la fecha actual.
  5. Pago e historial (2 min). Abrir “DEMO Presentación - Pago único”, venta V-1. Mostrar pago ficticio por S/ 1040.58 del 29/10/2026, incluido S/ 33.29 de mora; crédito liberado. Consultar Historial de pagos.
  6. Validación y cierre (1–2 min). Mostrar la tabla financiera y las pruebas. Si se desea registrar otra venta, usar productos DEMO y un cliente ficticio. No pagar la cuenta de tres cuotas antes de la exposición si se quiere conservar el ejemplo pendiente.

Las ventas históricas son importaciones académicas identificadas en auditoría; no fueron operaciones reales realizadas en septiembre. La mora pendiente cambiará cada día. Para otra fecha, tomar el importe recalculado de Cobranza. La cuenta de negocio existente se usa para operar; no compartir sus claves en la entrega.

2. Manual de uso

Acceso y contraseñas

  1. Escribir correo y contraseña.
  2. Introducir el código que llega al correo; revisar spam.
  3. Si se olvidó la contraseña, usar “Olvidé mi contraseña”. El enlace dura 15 minutos y es de un solo uso.
  4. “Mi contraseña” cambia la clave conocida y cierra las sesiones anteriores. El botón del ojo muestra u oculta lo escrito.

Administrador del Sistema

Gestiona Tiendas y Usuarios y accesos. Para crear una cuenta operativa, elegir “Administrador del negocio” y su tienda. Para otro gestor de plataforma, elegir “Administrador del sistema”. Este perfil no registra ventas ni pagos de un negocio.

Administrador del negocio

  1. Catálogo: crear producto o servicio; definir precio de contado y crédito, moneda, modalidad y stock cuando corresponda.
  2. Clientes: registrar cliente y cuenta. Informar identidad, contacto si existe, consentimiento, moneda, límite, tasas, corte, pago y máximo de cuotas. Una tasa nominal requiere capitalización.
  3. Nueva venta: elegir cuenta, ítems y cantidades, modalidad y plazo. Revisar la simulación y confirmar. El servidor valida crédito y stock.
  4. Cuenta: abrir venta y consultar cronograma. Las condiciones históricas quedan conservadas.
  5. Estados de cuenta: consultar cortes y abrir el reporte. Los cortes pendientes se procesan al visitar la aplicación cuando la configuración automática está activa.
  6. Cobranza: seleccionar cuenta y pagar el total exigible recalculado; no admite abonos parciales ni anticipa cuotas futuras.
  7. Historial y auditoría: revisar importe, fecha, medio y distribución del pago.
  8. Portal: invitar al cliente con un correo real que le pertenezca. Se envía un enlace de activación. No enviar invitaciones a correos ficticios.

Cliente

Activa la invitación, define contraseña y acepta la política; después accede con segundo factor. Solo consulta sus propias cuentas y estados. Los clientes DEMO no tienen un correo real ni portal activado.

6. Instalación y entrega

El ZIP contiene código, requisitos Python, dependencias npm declaradas, Dockerfile, configuración Render, manuales, pruebas y este anexo. No contiene exportaciones de la base pública, sesiones ni credenciales reales de los proveedores.

Para una copia local con Python y Node instalados, abrir PowerShell en la raíz:

python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
npm ci
npm run build
$env:APP_MODE="development"
$env:MAIL_PROVIDER="local"
.venv\Scripts\python -m backend.seed
.venv\Scripts\python -m backend.app

Abrir http://127.0.0.1:5000. La siembra de ejemplo solo actúa si la base está vacía; sus accesos son rosa@demo.local (negocio), pedro@demo.local (otro negocio), admin@demo.local (sistema) y juan@demo.local (cliente), con contraseña ficticia Barrio2026!. Esos accesos corresponden a la copia local; no son cuentas públicas. En desarrollo local el código de verificación aparece en pantalla.

Para la nube, consultar el manual de despliegue. Las notas que dicen “publicación pendiente” pertenecen a la preparación inicial; la web del encabezado ya está publicada. Las claves se configuran en el proveedor, nunca en GitHub.
